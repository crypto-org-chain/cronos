# v1.8 devnet test plan — tooling gaps and implementation order

Target: raise release confidence for v1.8 by running performance, regression, and
new-feature tests on a dedicated devnet. Compared versions are `v1.7.8-unsafe`
(baseline) and `v1.8.0-alpha` (candidate); a later `v1.8.0` will reuse the same
harness.

Source documents: `Cronos EVM v1.8 Performance Benchmarking and Network
Optimization` (proposal, tuning guide, schedule) and `Cronos v1.8 Upgrade Guide`.

## 1. What already exists

`remote-benchmark/` (branch `feat/benchmark`)

- Config-driven load generator: `fund`, `check`, `gen-txs`, `send-txs`, `bench`,
  `stats`.
- Cosmos (`MsgEthereumTx`, optional batching) and plain Ethereum wire modes.
- Round-robin sending across several endpoints.
- Sender strategies: `reuse` and `unique-per-tx` (conflict-free Block-STM).
- Live monitors for CometBFT mempool and Block-STM gauges.
- Consensus histogram scrape with a load-start baseline, so averages cover the
  load period instead of the whole process lifetime.
- Stall exclusion at 5x the 25th-percentile block time.
- Single-run self-contained HTML report with per-block and per-second charts.
- Local 1- and 3-validator pystarport runners plus a pytest suite.

`testground/`

- Docker/k8s orchestration, libp2p peer-ID derivation from `node_key.json`
  (`benchmark/peer.py`), config patching including `bootstrap_peers`.

`integration_tests/`

- 50 pytest modules, including `test_app_mempool.py`, `test_upgrade.py` (with
  the v1.8 migration checks) and `test_binary_compatibility.py`. All of them
  start their own local pystarport cluster.

## 2. Gaps

### 2.1 Measurement

These block any publishable "v1.8 is N% faster" statement.

- No machine-readable run record. Results are scraped text, so runs cannot be
  aggregated, compared, or archived.
- No repeated runs and no variance. A single sample per configuration is not
  enough to claim a delta.
- No comparison tool for v1.7.8 vs v1.8, or config A vs config B.
- The saturation gates from the tuning guide (gas utilisation >= 90%, pending
  mempool > 0 throughout, failed txs < 1%) are computed but never enforced, so
  an unsaturated run can be mistaken for a ceiling measurement.
- No warmup and drain trim, and the report headlines `peak_tps` while the tuning
  guide asks for median TPS over the sustained window.
- Only average and median block time. No p95 or p99.
- `dump_block_stats` and `dump_eth_block_stats` duplicate roughly 200 lines.
  This must be consolidated before more metrics are added.
- No run fingerprint. Nothing records binary version or the active feature flags
  (libp2p on/off, `mempool.type`, Block-STM workers, timeouts, gas limit), so
  two runs cannot be proven comparable.

### 2.2 Multi-node and devnet

- Stats come from the `primary` endpoint only. A 15-node devnet needs per-node
  series, height skew, and an app-hash agreement check.
- No resource telemetry (node_exporter). The proposal promises findings on
  memory leaks, disk IOPS, and bandwidth; none of that is collected.
- No consensus round diagnostics: rate of heights needing more than one round,
  timeout counters, missed proposals, block propagation latency.
- No soak mode. The sender is closed-loop over a fixed workload, so it cannot
  hold a steady rate for hours or report drift and leak trends.
- No sweep driver. Phase 1 step 3 and the whole of phase 2 are manual today.
- libp2p bootstrap peers are collected by hand, per the upgrade guide. There is
  no preflight check for UDP buffer sysctls, the transport-enabled log line, or
  peer connectivity.

### 2.3 Workloads

- Only `simple-transfer` and `erc20-transfer`. The proposal's state-contention
  testing for Block-STM (hot AMM pool, viral mint) has no workload to run.
- No mixed traffic profile and no integration with `cronos-tx-bot` gas
  mirroring.

### 2.4 Functional gaps between v1.7.8 and v1.8.0-alpha

91 commits, 187 files. No devnet coverage today for any of it:

- cosmos-sdk 0.53 to 0.54.3, ibc-go v11, cometbft v0.39, store/v2, rocksdb
  10.9.1.
- go-ethereum v1.16.9 with the Osaka hard fork enabled.
- App-side mempool: direct InsertTx, txpool RPC backed by `PendingTxs`, async
  post-Commit recheck, `mempool.recheck` handling, gossip TTL, TTL in blocks,
  tx cache, signature pre-verifier.
- libp2p transport replacing the CometBFT p2p stack.
- 16 bug fixes, several security relevant: `SendCroToIbc` contract
  authorisation, CRC21 mapping restrictions, source-denom immutability,
  `ReplayBlock` bounds, versiondb non-leaf restore, memiavl fd leak.
- Upgrade handler work: staking pending-slot population, stale IBC client key
  prune, CroBridge address params.

## 3. Implementation plan

### P0 — comparability core (`remote-benchmark`)

1. Refactor `stats.py` into one `compute_metrics(series)` plus renderers, and
   drop the eth/cosmos duplication. Add p95 and p99 block time, warmup and
   drain trim, and median TPS as the headline.
2. Add `results.py` writing a run-record JSON for every `bench`: config
   snapshot, node roster with per-node fingerprint (version from `/abci_info`,
   resolved `mempool.type`, libp2p enabled, Block-STM workers, consensus
   timeouts, block gas limit), per-block series, summary metrics, telemetry
   snapshots, validity verdict.
3. Enforce saturation gates behind `--require-saturation`: non-zero exit with
   the failing reasons when gas utilisation, pending mempool, or failure rate
   miss their thresholds.
4. Add `bench --repeat N` with aggregation (median of medians, min, max,
   standard deviation).
5. Add `compare A.json B.json`: delta table, side-by-side HTML, percentage gain
   per metric, an explicit "spreads overlap, not significant" flag, and a diff
   of the two run configurations.

### P1 — devnet observability

6. Collect block series and telemetry from every endpoint. Add height skew and
   a per-height app-hash agreement check as a state-divergence detector.
7. Extend consensus diagnostics: multi-round rate, timeout and missed-proposal
   counters, block-part propagation, per-validator scrape.
8. Add `resources.py`: node_exporter and Go runtime scrape (RSS, heap,
   goroutines, disk IOPS and bytes, network bytes) sampled into the run record.
9. Add `soak --duration`: open-loop pacer aiming at a target rate instead of
   dumping fixed batches, periodic checkpoints, and trend fits on RSS, TPS, and
   block time to produce a leak and degradation verdict.
10. Add `sweep matrix.yaml`: parameter matrix (gas limit ramp, timeout sets,
    `mempool.type`, worker counts, memiavl and rocksdb settings), a pluggable
    apply-config hook over ssh or ansible plus restart, automatic stop on
    degradation criteria, one run record per cell, and a sweep summary report.
11. Add libp2p tooling. Reuse `testground/benchmark/benchmark/peer.py` to derive
    peer IDs and generate `bootstrap_peers` for N nodes. Add a `preflight`
    command checking UDP buffer sysctls, the transport-enabled log line, the
    resolved mempool type, and the peer connectivity matrix.

### P2 — workloads

12. Add contended tx types: `erc20-transfer-hot` (all senders to one receiver,
    single hot slot), `uniswap-swap` against a seeded pool, and `nft-mint`
    against a shared counter, plus a weighted mix profile. Seed state by
    extending `scripts/devnet-local/patch_erc20_genesis.py`. Report the re-execution ratio
    delta as the Block-STM contention result.

### P3 — functional and regression suite

New `devnet_tests/` pytest package targeting remote RPC endpoints with a funded
key, importing helpers from `integration_tests/utils.py`.

13. Coverage:
    - `rpc-diff` differential tool. Replay one request corpus (blocks,
      transactions, receipts, logs, traces, `eth_call`, `estimateGas`,
      `feeHistory`, access lists, txpool, filters) against a v1.7.8 node and a
      v1.8 node over identical history, then diff the responses. This is what
      backs the "100+ methods, over 90% equivalence" claim and catches
      regressions from the go-ethereum bump.
    - Osaka and EIP behaviour: EIP-7825 transaction gas cap (suspected
      unenforced), EIP-7702, EIP-2935, floor data gas, the EIP-1559 balance
      check, blob-tx rejection.
    - App-mempool behaviour under load: nonce gaps, replacement and underpriced
      rejection, the `recheck = false` path, txpool contents while saturated,
      direct InsertTx, gossip-TTL de-duplication, eviction by
      `mempool-ttl-num-blocks`, `max-txs` back-pressure, and the
      `tx-cache-max-tx-bytes` startup validation.
    - State safety: app-hash agreement (from item 6), exported-genesis equality
      across versions, versiondb restore including the non-leaf fix, and a
      historical-query soak for the memiavl fd leak.
    - Security fixes on chain: `SendCroToIbc` contract authorisation, CRC21
      zero-address and precompile-range rejection, denom immutability, the
      unblockable list, `ReplayBlock` bounds.
    - Upgrade rehearsal: cosmovisor in-place upgrade from `v1.7.8-unsafe` to
      `v1.8.0-alpha` at a set height while load is running. Assert the
      migrations (staking pending slots, stale IBC key prune, CroBridge
      params), no halt, no divergence, then run a rollback drill. Reuse the
      assets in `integration_tests/test_upgrade.py`.
    - IBC v11, ICA, and hermes smoke tests. Already covered: hermes relay via
      `integration_tests/test_ibc_rly.py`, ICA via `integration_tests/test_ica*.py`
      and the ICA module wiring in `app/app.go`, ibc-go v11.1.0 already pinned
      in `go.mod`.
14. CI: a short one-validator smoke run plus pytest for the new modules, so the
    tooling does not rot between releases. Done: `.github/workflows/devnet-smoke.yml`
    runs `scripts/run-devnet-smoke.sh` against `scripts/cronos-single-devnet.yaml`.

## 4. Sequencing

1. P0 first. Nothing is reportable without it.
2. Items 6 and 11 before devnet bring-up. Bootstrap peer generation and the
   divergence check are bring-up blockers.
3. P2 and item 10 before the sweeps.
4. P3 runs in parallel, by whoever is not on the performance track.

Rough effort: P0 three to four days, P1 five to six, P2 two to three, P3 five to
eight.

## 5. Assumptions and boundaries

- v1.7.8 has neither the app-side mempool nor libp2p. The baseline therefore
  runs the flood mempool over the CometBFT p2p stack, and feature isolation is
  v1.8 against v1.8: CometBFT p2p with flood mempool versus libp2p with the app
  mempool.
- AWS provisioning and the Prometheus/Grafana stack stay with devops. This
  tooling ships config generators, `bootstrap_peers` output, scrape targets, and
  an apply-config hook the sweep driver calls over ssh or ansible. No
  Terraform or Ansible inventory lands in this repository.
- The functional suite lives in a new `devnet_tests/` package, so the existing
  local pystarport fixtures and CI suite are untouched.
